# 기능 범위

이 문서는 현재 구현된 기능과 향후 확인이 필요한 기능 후보를 정리합니다.
구현 상세는 `domain`, `api`, `database` 문서를 기준으로 확인합니다.

## 목적

- 기능 범위를 제품 관점에서 빠르게 확인합니다.
- 구현된 기능과 아직 확정되지 않은 기능 후보를 구분합니다.
- 새 기능 작업 전에 기존 범위와 충돌하는지 확인할 수 있게 합니다.

## 현재 구현된 기능

### Identity

- 회원가입
- 로그인과 access/refresh token 발급
- 토큰 재발급
- 로그아웃과 refresh token 폐기
- 비밀번호 변경
- 관리자 생성
- 임시 비밀번호 변경 필요 상태 관리

### Catalog

- 공연장 생성과 목록 조회
- 층, 열, 좌석 생성
- 좌석 등급 생성
- 리소스 정책 생성
- 리소스 요금 생성
- Closure Table 기반 리소스 계층 관리

### Booking

- 공연 회차 목록 조회
- 공연 회차 생성
- 회차 오픈
- 좌석 현황 조회
- 회차 마감
- 회차 취소
- 좌석 임시 점유
- 예약 확정
- 예약 취소
- 내 예약 목록 조회
- 예약 상세 조회
- 만료된 잠금 자동 해제

## 향후 확인이 필요한 기능 후보

다음 기능은 코드와 현재 문서에서 확정 범위를 확인하지 못했습니다.
새 작업으로 진행하기 전에 `work-items` 문서나 사용자 확인을 통해 범위를 정해야 합니다.

- 결제 연동과 결제 결과 반영
- 환불, 취소 수수료, 부분 취소 정책
- 예매 대기열과 대량 트래픽 제어
- 좌석 추천 또는 자동 배정
- 공연/회차 검색과 필터링 고도화
- 관리자 운영 화면
- 사용자 알림
- 운영 감사 로그 확장
- 회원 탈퇴와 개인정보 처리
- 공연/좌석 데이터 bulk import

## 범위 판단 기준

새 기능을 추가할 때 다음 질문을 먼저 확인합니다.

- 제품 목표인 좌석 예약 데이터 무결성과 직접 관련이 있는가.
- 현재 구현된 Identity, Catalog, Booking 중 어느 모듈의 책임인가.
- 결제, 개인정보, 운영 리스크가 걸려 있어 사용자 확인이 필요한가.
- 기존 API/DB 계약을 깨는가.
- 동시성, 트랜잭션, 상태 전이에 영향을 주는가.
- 작업 결과를 `domain`, `api`, `database`, `project` 문서로 승격해야 하는가.
