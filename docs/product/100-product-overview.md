# 제품 개요

이 문서는 현재 제품 목표와 범위, 확인 필요 사항을 정리합니다.

## 목적

- 제품 방향과 현재 범위를 코드 구조 문서와 분리합니다.
- 기능 구현 전에 제품 목표와 제외 범위를 확인할 수 있게 합니다.
- 확인되지 않은 기획 내용을 추측하지 않게 합니다.

## 현재 제품 목표

현재 확인된 제품 목표는 다음과 같습니다.

- 공연/이벤트 좌석 예약 백엔드를 제공합니다.
- 좌석 단위 동시 요청 상황에서 중복 점유를 방지합니다.
- 공연장, 층, 열, 좌석의 계층형 리소스를 관리합니다.
- 공연 회차별 좌석 슬롯과 예약 생명주기를 관리합니다.
- 좌석 임시 점유와 예약 확정을 분리해 결제 전 선점 흐름을 지원합니다.
- 잠금 이력을 남겨 좌석 상태 변화의 감사 가능성을 확보합니다.

## 현재 범위

현재 코드와 문서에서 확인되는 범위는 다음과 같습니다.

- JWT 기반 회원/관리자 인증
- 공연장/층/열/좌석 리소스 관리
- 좌석 등급, 리소스 정책, 리소스 요금 관리
- 공연 회차 생성, 오픈, 마감, 취소
- 좌석 현황 조회
- 좌석 임시 점유, 예약 확정, 예약 취소
- 내 예약 목록과 예약 상세 조회
- 만료된 좌석 잠금 자동 해제

## 제외 또는 보류 범위

다음 내용은 아직 확정하지 않습니다.

- 실제 결제 연동
- 대기열 또는 트래픽 제어 기능
- 알림 기능
- 좌석 추천 기능
- 프론트엔드 사용자 화면
- 관리자 운영 UI
- 운영 모니터링과 장애 대응 체계
- 수익화 정책

## 확인 필요 사항

- 핵심 사용자 유형
- 결제 연동 여부와 예약 확정 기준
- 결제 실패, 결제 취소, 환불 정책
- 좌석 임시 점유 TTL의 제품 정책
- 공연 취소 시 사용자 통지와 보상 정책
- 관리자 운영 도구의 상세 범위
- 예매 오픈 시 목표 트래픽과 대기열 필요성
- 개인정보 보존, 회원 탈퇴, 계정 삭제/익명화 정책
- 운영 환경에서 Swagger UI 노출 여부
